Configuration

kvist has two places for settings. The server's file decides what may be published and where; a settings note in your vault decides how the site looks.

Which place?

kvist.toml server_site.md vault
WhereOn the server, next to docker-compose.ymlA note in your vault, usually Kvist/_site.md
HoldsPublish rules, the site's address, limits, Cloudflare, the themeTitle, description, home page, menu links, theme settings
Takes effectAfter docker compose restart kvist, on the next publishOn the next publish
Why thereA device or synced vault can't loosen the rulesYou can change the look from Obsidian, on any device

The plugin's own settings (server URL, site, token) are in Obsidian under Settings → kvist; see below.

kvist.toml uses TOML: key = "text", key = true, key = 10, lists like ["a", "b"], and [sections]. Lines starting with # are comments. The settings note uses ordinary Obsidian properties.

Server: kvist.toml

data_dir = "/data"
listen   = "0.0.0.0:8080"

[[site]]
id       = "garden"
base_url = "https://garden.example.com"
title    = "My garden"
serve    = true

  [site.publish]
  always_public_folders = ["Kvist"]
  exclude_folders       = ["Templates", "Private"]
  expose_frontmatter    = ["stage"]

Top level

KeyDefault
data_dirrequiredWhere kvist stores everything. /data in Docker.
listen"127.0.0.1:8080"Address and port to listen on. "0.0.0.0:8080" in Docker, so it can be reached from outside the container; docker-compose.yml decides who can.
sync_ttl"1h"How long an unfinished upload may take.
themes_dir"themes"Folder with extra themes, searched before the built-in ones.
tls_cert, tls_keynoneServe HTTPS directly, with a certificate you renew yourself. Not needed behind a proxy that handles HTTPS (Domains and HTTPS).

[[site]]

One block per site. A server can host several sites, each with its own [[site]] block, domain and tokens.

KeyDefault
idrequiredShort name used by the plugin and the commands: lowercase letters, digits and dashes.
base_urlrequiredThe site's address, e.g. https://garden.example.com. Must be the root of a domain; sub-paths are planned.
title, description, authoremptyDefaults; the settings note can override them.
language"en"Language code for pages and feeds, and for the theme's words (see Customizing).
strict_line_breaksfalseRender a single line break as a space (Obsidian's Strict line breaks) instead of a line break. The settings note can override it.
root_folderautomaticThe vault folder that is the site's root. Its notes and folders are published as if it were the whole vault: Kvist/Garden/Soil.md is at /garden/soil/, and the menu starts with Garden, not Kvist. By default it is the only folder in always_public_folders, if there is exactly one. "/" keeps the vault's own layout (/kvist/garden/soil/). Notes outside it keep their path, so a #public note at the vault's top is at /its-name/. When this changes, old addresses redirect to the new ones.
servefalseLet kvist serve the site itself. Keep true with the Docker setup.
theme"garden"The theme: a built-in name, a folder in themes_dir, or a path.
theme_overridesnoneFolder whose files replace the theme's files with the same path.
[site.theme_params]Theme settings; the settings note's values win.

[site.publish]

See Publishing notes for how the rules combine.

KeyDefault
always_public_folders[]Folders whose notes are public. "/" means the whole vault.
exclude_folders[]Folders that are never published, whatever their notes say.
public_tag"public"Tag that publishes a note.
private_tag"private"Tag that keeps a note private.
frontmatter_key"publish"Property that publishes (true) or hides (false) a note.
expose_frontmatter[]Note properties the theme may show. The garden theme uses stage.
attachment_extensionspng, jpg, jpeg, gif, webp, svg, avif, pdf, mp3, m4a, ogg, wav, mp4, webm, canvasFile types that may be published. Leave out canvas to publish no canvases.
strip_image_metadatatrueRemove location, camera and author data from JPEG, PNG and WebP images.
unpublished_links"warn"Links to private notes: "ignore", "warn", or "error" to stop the build.
unpublished_embeds"warn"The same for embeds.

[site.limits]

KeyDefault
max_file_size52428800 (50 MiB)Largest file, in bytes.
max_files20000Most notes and files in one site.

[site.retention]

KeyDefault
revisions10Published versions kept for rollback.
builds3Built copies of the site kept on disk.

[site.cloudflare]

Clears Cloudflare's cache after every publish. See Running the server.

Key
zone_idThe zone's ID. Purging is off without it.
api_token_envName of the environment variable with the API token, e.g. "CF_API_TOKEN".
api_token_fileOr: a file containing the token.

Vault: the settings note

A note called _site.md, in any folder. It's never published as a page. Create or open it with kvist: Open site settings note.

---
title: Ada's garden
description: Notes on what I'm learning
author: Ada
language: en
home: "[[Welcome]]"
groups: [articles, projects]
accent: "#8a4f9e"
---
## Links
- [About](/about/)
- [[Reading list]]
Property
title, description, author, languageOverride the server's values.
homeA published note to use as the home page: "[[Welcome]]" or a vault path.
groupsTags that group the menu.
strict_line_breakstrue: a single line break is a space, not a line break.
imageDefault social preview image: "[[preview.png]]", a vault path or a web address.
faviconThe browser tab icon: "[[icon.png]]", a vault path or a web address. PNG or SVG.
avatar (or logo), bio, profile_linksThe profile in the menu.
analytics, analytics_id, analytics_urlVisitor statistics with Plausible, Umami or GoatCounter.
Anything elseA theme setting.

Empty properties keep their default. Obsidian's own properties (tags, aliases, cssclasses) are ignored. Server-only keys such as base_url or exclude_folders are ignored with a warning in the publish report.

Menu links are the list items in the note's text that are a single link: [Text](https://…), [Text](/path/), [[Note]] or [[Note|Text]]. Links to notes that aren't published are left out with a warning. Links inside %% comments %% and code blocks don't count, so you can keep examples there.
