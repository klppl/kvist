Getting started

This guide takes you from an empty server to your first published notes. You set up the server once, connect Obsidian, and choose what is public.

Before you begin

You need a Linux server with Docker installed, a domain name you can point at it, and Obsidian on your computer. In the examples, the site lives at garden.example.com; replace that with your own address everywhere.

Part 1: the server

  1. Point your domain at the server

    At your DNS provider, add an A record for your site's name (for example garden) with your server's IP address. Add an AAAA record too if the server has an IPv6 address. Make sure ports 80 and 443 are open in the server's firewall.

    DNS changes can take a few minutes to arrive. The next steps need them, because the server asks Let's Encrypt for an HTTPS certificate for that name.

  2. Download the three server files

    Log in to the server with SSH and run:

    mkdir -p ~/kvist && cd ~/kvist
base=https://raw.githubusercontent.com/klppl/kvist/main/deploy
curl -fsSLO $base/docker-compose.yml -O $base/Caddyfile -O $base/kvist.toml

    You now have:

    FileWhat it does
    docker-compose.ymlRuns two containers: kvist, and Caddy, which handles HTTPS.
    CaddyfileTells Caddy your domain name.
    kvist.tomlThe kvist server settings: your site's address, title and publish rules.

  3. Put in your domain and rules

    In Caddyfile, replace garden.example.com with your domain. In kvist.toml, set base_url and title, and look at the publish rules:

    data_dir = "/data"
listen   = "0.0.0.0:8080"

[[site]]
id       = "garden"                       # the name you use in the plugin
base_url = "https://garden.example.com"   # your address
title    = "My garden"
theme    = "garden"
serve    = true

  [site.publish]
  always_public_folders = ["Kvist"]              # everything in here is public
  exclude_folders       = ["Templates", "Private"] # never public
  expose_frontmatter    = ["stage"]

    These defaults mean: notes in a Kvist folder are published, notes with a #public tag are published from anywhere, and Templates and Private never are. Everything else stays private. You can change this any time; Publishing notes explains the options.

    Leave data_dir and listen as they are. They refer to paths inside the container.

  4. Start it

    docker compose up -d

    Docker downloads kvist and Caddy and starts both. Caddy gets an HTTPS certificate on its own. Check that kvist answers:

    curl https://garden.example.com/api/v1/info

    You should see something like {"protocol":{"min":1,"max":1},"server":"…"}. The site itself shows “404 not found” until you publish for the first time. That's expected.

  5. Create a token for your computer

    A token is the password the plugin uses to publish. Create one per device, so you can revoke a lost phone without touching the others:

    docker compose exec kvist kvist token create --site garden --name laptop

    It prints a token that starts with kvist_. Copy it now: it is shown only once, and the server only keeps a fingerprint of it.

Part 2: the Obsidian plugin

  1. Download the plugin

    kvist isn't in Obsidian's community plugin list yet, so you install it by hand. Download kvist-plugin.zip; the link always gives you the newest version. Unzip it: it holds a kvist folder with the whole plugin.

  2. Put it in your vault

    Move the kvist folder into your vault's .obsidian/plugins/ folder, so you have <vault>/.obsidian/plugins/kvist/. Create plugins if it doesn't exist. The .obsidian folder is hidden: on a Mac, press Cmd+Shift+. in Finder to show it. Or from a terminal (replace the path with your vault's):

    VAULT=~/Documents/MyVault
mkdir -p "$VAULT/.obsidian/plugins"
curl -L -o /tmp/kvist-plugin.zip https://github.com/klppl/kvist/releases/latest/download/kvist-plugin.zip
unzip -o /tmp/kvist-plugin.zip -d "$VAULT/.obsidian/plugins"

    In Obsidian, open Settings → Community plugins. If Restricted mode is on, turn it off. Click the reload button next to Installed plugins and switch kvist on.

  3. Connect it to your server

    Open Settings → kvist and fill in:

    SettingValue
    Server URLhttps://garden.example.com
    Sitegarden (the id from kvist.toml)
    TokenThe token from step 5

    Press Test. You should see connected to “garden”. If not, see Troubleshooting.

Part 3: your first publish

  1. Choose a few public notes

    With the default rules, the easiest start is to create a folder called Kvist in your vault and put a note or two in it. (The name is just the default. Use any folder you like by changing always_public_folders in kvist.toml.) To publish a note that lives elsewhere, add the #public tag to it, or run the command kvist: Toggle publish for current note, which sets publish: true in its properties.

  2. Publish

    Open the command palette (Cmd+P or Ctrl+P) and run kvist: Publish now. After a few seconds you see published 2 notes, and the kvist icon in the status bar turns into ●.

    Open your address in a browser. Your notes are there.

  3. Check the report

    Click the kvist status in the status bar, or run kvist: Open publish report. It lists what is public, and anything worth a look: links from public notes to private ones (shown as plain text on the site), embeds that were left out, and warnings from the server.

Part 4: make it yours

The site's title, home page, menu and colors are set in a note in your vault called _site.md, the settings note. You edit it in Obsidian like any other note, on any device, and changes go live with your next publish. It's never published as a page.

Run kvist: Open site settings note from the command palette (or press Open settings note in the plugin's settings). The first time, it creates Kvist/_site.md with every setting ready to fill in:

---
title: Ada's garden
description: Notes on what I'm learning and building
home: "[[Welcome]]"
groups: [articles, projects, books]
---
Settings for your kvist website. …

Publishing from more devices

For each extra device (another computer, your phone):

  1. Create a new token on the server with a new --name.
  2. Make sure the plugin files are in that device's copy of the vault. If you sync your vault with Obsidian Sync or iCloud, including the .obsidian folder, they usually arrive by themselves.
  3. Enable the plugin and paste the new token. The server URL and site sync with your vault; the token never does.

If you turn on Publish automatically, do it on one device only. Here's why.
